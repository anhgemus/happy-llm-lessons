The Evolution of Text Representations

From sparse one-hot vectors to dense contextual embeddings — the representational journey that made every modern LLM possible.

Chapter 1 Foundations Embeddings

The Lesson

Before any LLM can understand language, it needs a way to represent text as numbers. This seems simple — just assign each word an ID, right? — but the quality of that representation is what separates a model that recognizes patterns from one that understands meaning. The evolution of text representations is arguably the most important thread in NLP history, because every breakthrough in model capability traces back to a better way of encoding words.

The journey has three major leaps:

1970s–2010s
One-Hot Encoding (Bag of Words)

Each word is a vector of length V (vocabulary size), with a single 1 at the word's position and 0 everywhere else. For a vocabulary of 50,000 words, "cat" is a 50,000-dimensional vector with one non-zero entry. The problem? Every word is equidistant from every other word. The dot product of "king" and "queen" is exactly the same as "king" and "pizza" — both are zero. No semantic relationship can be captured.

2013
Word2Vec — Dense Static Embeddings

Word2Vec learns dense, low-dimensional vectors (typically 100–300 dimensions) by predicting words from their context. The magic: words with similar meanings end up close together in vector space. "king" − "man" + "woman" ≈ "queen." But the embedding is static — the word "bank" has the same vector whether it means a river bank or a financial institution. One word, one vector, no matter the context.

2018
ELMo → BERT — Contextual Embeddings

ELMo was the first to produce context-dependent word representations. The word "bank" gets different vectors in "river bank" vs. "savings bank." BERT took this further with bidirectional Transformers, producing representations that capture not just local context but the full sentence. This is the foundation every modern LLM builds upon.

Each leap solved a fundamental limitation of the previous approach. One-hot encoding couldn't capture similarity. Word2Vec captured similarity but not context. ELMo and BERT captured context but were computationally expensive. Modern LLMs inherit all of these ideas: dense embeddings, contextual representations, and the principle that meaning emerges from the relationship between words, not from words in isolation.

Concrete Example

Let's see the difference between one-hot encoding and Word2Vec embeddings in practice:

import numpy as np
from gensim.models import Word2Vec

# --- One-hot encoding ---
# Vocabulary: ["king", "queen", "cat", "dog", "pizza"]
vocab = {"king": 0, "queen": 1, "cat": 2, "dog": 3, "pizza": 4}
vocab_size = len(vocab)

def one_hot(word):
    vec = np.zeros(vocab_size)
    vec[vocab[word]] = 1
    return vec

king_vec = one_hot("king")
queen_vec = one_hot("queen")
pizza_vec = one_hot("pizza")

# Cosine similarity between any pair of one-hot vectors is always 0
from numpy.linalg import norm
cos_sim = lambda a, b: np.dot(a, b) / (norm(a) * norm(b))

print("=== One-Hot Similarities ===")
print(f"king vs queen:  {cos_sim(king_vec, queen_vec):.4f}")
print(f"king vs pizza:  {cos_sim(king_vec, pizza_vec):.4f}")
print("→ Both are 0.0000. No semantic information at all.\n")

# --- Word2Vec embeddings ---
# Train on a small corpus
sentences = [
    ["the", "king", "is", "powerful", "and", "rules", "the", "kingdom"],
    ["the", "queen", "is", "powerful", "and", "rules", "the", "kingdom"],
    ["the", "cat", "is", "small", "and", "lives", "in", "the", "house"],
    ["the", "dog", "is", "loyal", "and", "lives", "in", "the", "house"],
    ["the", "king", "and", "the", "queen", "rule", "together"],
    ["the", "cat", "and", "the", "dog", "play", "together"],
]

model = Word2Vec(sentences, vector_size=50, window=3, min_count=1, epochs=100)

king_emb = model.wv["king"]
queen_emb = model.wv["queen"]
cat_emb = model.wv["cat"]
dog_emb = model.wv["dog"]

print("=== Word2Vec Similarities ===")
print(f"king vs queen:  {cos_sim(king_emb, queen_emb):.4f}")
print(f"king vs cat:    {cos_sim(king_emb, cat_emb):.4f}")
print(f"cat vs dog:     {cos_sim(cat_emb, dog_emb):.4f}")
print("→ king/queen and cat/dog pairs are more similar to each other\n")

# --- The famous analogy: king - man + woman ≈ queen ---
print("=== Vector Arithmetic ===")
print(f"king vector shape: {king_emb.shape}")
print(f"king embedding (first 5 dims): {king_emb[:5].round(4)}")
print(f"queen embedding (first 5 dims): {queen_emb[:5].round(4)}")

Now let's see how contextual embeddings solve the polysemy problem that Word2Vec can't handle:

from transformers import AutoTokenizer, AutoModel
import torch

tokenizer = AutoTokenizer.from_pretrained("bert-base-uncased")
model = AutoModel.from_pretrained("bert-base-uncased")
model.eval()

# The word "bank" in two different contexts
sentence_a = "I deposited money at the bank"
sentence_b = "I sat on the bank of the river"

def get_word_embedding(sentence, target_word):
    inputs = tokenizer(sentence, return_tensors="pt")
    with torch.no_grad():
        outputs = model(**inputs)
    # Get token embeddings (last hidden state)
    embeddings = outputs.last_hidden_state[0]  # (seq_len, 768)
    tokens = tokenizer.convert_ids_to_tokens(inputs.input_ids[0])

    # Find the target word token
    for i, token in enumerate(tokens):
        if token.replace("##", "") == target_word:
            return embeddings[i].numpy(), token

emb_a, tok_a = get_word_embedding(sentence_a, "bank")
emb_b, tok_b = get_word_embedding(sentence_b, "bank")

sim = cos_sim(emb_a, emb_b)
print(f"Token A: '{tok_a}' in '{sentence_a}'")
print(f"Token B: '{tok_b}' in '{sentence_b}'")
print(f"Cosine similarity of contextual embeddings: {sim:.4f}")
print(f"→ Lower similarity = BERT captures the different meanings!")

# Compare with static Word2Vec (same vector regardless of context)
print(f"\nWith static Word2Vec: bank always has the SAME vector.")
print(f"Cosine similarity would be: 1.0000 (identical)")

The output typically shows a similarity of around 0.4–0.6 for the two "bank" embeddings, compared to 1.0 for static embeddings. This is the fundamental insight: the same word should have different representations in different contexts, and only contextual models can achieve this.

🔑 Key Takeaway

The evolution from one-hot → dense static → contextual embeddings is the single most important progression in NLP. Each step solved a fundamental representational limitation: one-hot vectors can't encode similarity, static embeddings can't encode context, and contextual embeddings (the current state of the art) encode both. Every modern LLM — from BERT to GPT to LLaMA — uses dense, contextual embeddings as its foundational representation layer. Understanding this progression helps you understand why LLMs work, not just how to use them.

Why It Matters

When you're working with LLMs in production, representation quality is often the bottleneck you can't see. If your fine-tuning data uses poor tokenization or your domain has vocabulary not well-represented in the pre-trained embedding space, the model will struggle — no matter how much compute you throw at it. Understanding the embedding layer helps you diagnose these failures.

It also informs your architectural choices. For tasks where context matters less (keyword matching, simple classification on short texts), static embeddings like Word2Vec or FastText can be surprisingly effective and orders of magnitude cheaper. For tasks requiring deep semantic understanding (summarization, reasoning, translation), you need contextual embeddings. Knowing where each approach fits is a practical skill that separates LLM engineers from LLM API callers.

Finally, the representational journey continues. Modern research explores multimodal embeddings (text + image + audio in one space), instruction-tuned embeddings, and adapters that modify representations for specific domains without retraining the full model. The core principle remains the same: better representations = better understanding.
