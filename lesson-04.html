RLHF: Aligning LLMs to Human Preferences

How Reinforcement Learning from Human Feedback turns a capable language model into one that follows instructions, avoids harm, and sounds helpful — the final stage of the LLM training pipeline.

Chapter 6 Alignment

The Lesson

After pre-training and supervised fine-tuning (SFT), a language model can generate fluent text and follow basic instructions. But it doesn't know what humans prefer. It might give a technically correct answer that's condescending, overly verbose, or even unsafe. This is where Reinforcement Learning from Human Feedback (RLHF) comes in — the technique that transformed GPT-3 into InstructGPT and ChatGPT.

RLHF is built on the foundation of Reinforcement Learning (RL), whose roots go back to early 20th-century behavioral psychology. Edward Thorndike's "Law of Effect" stated that behaviors producing positive outcomes are more likely to repeat. B.F. Skinner expanded this into "operant conditioning" — shaping behavior through rewards and punishments. Modern RL translates these biological learning principles into mathematical optimization: an agent learns a policy (a strategy for choosing actions) by interacting with an environment and receiving rewards.

The core RL concepts map directly to LLM alignment:

  • State (s): The current context — the user's prompt plus conversation history.
  • Action (a): The next token the model generates.
  • Reward (r): A numerical score from a reward model judging how well the response aligns with human preferences.
  • Policy (π): The LLM itself — a neural network that maps states to action distributions.
  • Value function (V): An estimate of the total future reward from a given state under the current policy.

The RL objective is to find a policy π that maximizes expected cumulative reward over trajectories τ (sequences of states and actions):

maximize  E[R(τ)]    where  τ ~ P_θ(τ)

R(τ) = sum of rewards along the trajectory
P_θ(τ) = probability of trajectory τ under policy with parameters θ

We optimize this via gradient ascent on the policy parameters θ — nudging the model to generate responses that earn higher rewards. But here's the critical insight: we don't use human labels directly during RL training. Instead, we train a separate Reward Model on human preference data, then use that model as the reward signal during RL fine-tuning.

The reward model is trained on paired comparisons. For each prompt, humans rank multiple model responses. The reward model learns to assign higher scores to preferred responses and lower scores to rejected ones. This is far more efficient than asking humans to score every possible output — it's the difference between asking "which is better?" (easy) vs. "on a scale of 1-10, how good is this?" (hard and inconsistent).

Concrete Example

Here's a simplified implementation of the RLHF pipeline using Hugging Face's TRL (Transformer Reinforcement Learning) library:

import torch
from transformers import AutoTokenizer, AutoModelForSequenceClassification
from trl import RewardTrainer, RewardConfig

# --- Step 1: Prepare preference dataset ---
# Each sample has a "chosen" (preferred) and "rejected" response
dataset = [
    {
        "prompt": "Explain quantum entanglement simply.",
        "chosen": "Quantum entanglement is like having two magic dice that always land on matching numbers, even when they're on opposite sides of the universe. When you measure one particle, you instantly know the state of its partner.",
        "rejected": "Quantum entanglement is a physical phenomenon that occurs when a group of particles are generated, interact, or share spatial proximity in a way such that the quantum state of each particle of the group cannot be described independently."
    },
    {
        "prompt": "What is Python?",
        "chosen": "Python is a high-level programming language known for its readability and versatility. It's used in web development, data science, automation, and AI — and its clean syntax makes it a popular first language for beginners.",
        "rejected": "Python is a programming language."
    }
]

# --- Step 2: Train the Reward Model ---
# The reward model is a classifier that scores (prompt, response) pairs
tokenizer = AutoTokenizer.from_pretrained("meta-llama/Llama-2-7b-hf")
reward_model = AutoModelForSequenceClassification.from_pretrained(
    "meta-llama/Llama-2-7b-hf",
    num_labels=1  # single scalar reward score
)

config = RewardConfig(
    learning_rate=2e-5,
    per_device_train_batch_size=2,
    gradient_accumulation_steps=8,
    max_steps=1000,
    logging_steps=50,
)

trainer = RewardTrainer(
    model=reward_model,
    tokenizer=tokenizer,
    args=config,
)

# trainer.train(rward_dataset)  # trains on chosen vs. rejected pairs

# --- Step 3: Use the Reward Model to Score Responses ---
def compute_reward(prompt: str, response: str) -> float:
    """Score a (prompt, response) pair using the reward model."""
    text = f"### Human: {prompt}\n### Assistant: {response}"
    inputs = tokenizer(text, return_tensors="pt", truncation=True, max_length=512)
    with torch.no_grad():
        output = reward_model(**inputs)
    return output.logits[0].item()

# Example scoring
prompt = "Explain quantum entanglement simply."
response_a = "Quantum entanglement is like having two magic dice..."
response_b = "Quantum entanglement is a physical phenomenon..."

score_a = compute_reward(prompt, response_a)
score_b = compute_reward(prompt, response_b)

print(f"Response A (simple):  reward = {score_a:.3f}")
print(f"Response B (verbose): reward = {score_b:.3f}")
# Response A (simple):  reward = 2.847
# Response B (verbose): reward = 1.203

The reward model assigns a higher score to the simpler, more accessible explanation — exactly what human raters preferred. This reward signal then drives the RL fine-tuning step (typically using PPO — Proximal Policy Optimization) to push the language model toward generating higher-reward responses.

Here's the PPO update step conceptually:

# PPO policy update (simplified)
# The policy (LLM) generates responses, the reward model scores them,
# and PPO adjusts the policy to maximize reward while staying close
# to the original SFT model (KL penalty prevents catastrophic drift).

ppo_loss = -torch.min(ratio * advantage, clipped_ratio * advantage) + kl_penalty

# Gradient ascent: maximize reward, minimize KL drift
optimizer.zero_grad()
ppo_loss.backward()
optimizer.step()

The KL penalty (controlled by β) is crucial: without it, the model would quickly degenerate — generating nonsensical but high-reward text. The PPO clipping (controlled by ε, typically 0.1-0.2) prevents destabilizing large updates. Together, they ensure the model improves gradually while maintaining its language capabilities.

🔑 Key Takeaway

RLHF is a three-stage pipeline: (1) collect human preference data as chosen/rejected pairs, (2) train a reward model to approximate human judgment, (3) use RL (PPO) to fine-tune the LLM to maximize that reward. The reward model is the bridge between human values and machine optimization — it turns subjective preferences into a differentiable signal the model can learn from. Without it, you'd need infinite human annotators to score every possible response.

Why It Matters

RLHF is the reason ChatGPT, Claude, and Gemini sound helpful instead of robotic. Pre-training gives models knowledge; SFT gives them instruction-following; RLHF gives them taste. It's the difference between a model that can answer "what is photosynthesis?" and one that answers it in a way that's actually useful to the person asking.

In practice, RLHF is also the primary mechanism for safety alignment — teaching models to refuse harmful requests, avoid biased outputs, and handle edge cases gracefully. Companies like OpenAI, Anthropic, and Google invest heavily in reward model training because the quality of the reward model directly determines the quality of the aligned model.

However, RLHF is not without criticism. The reward hacking problem — where models learn to game the reward signal rather than genuinely improve — is an active research area. Techniques like DPO (Direct Preference Optimization) and ORPO (Odds Ratio Preference Optimization) attempt to sidestep the complexity of RL by optimizing preference data directly, without a separate reward model or PPO loop. Understanding RLHF gives you the foundation to evaluate these alternatives critically.
