The 80/10/10 MLM Masking Strategy

Source: Happy-LLM Chapter 3 — Pre-trained Language Models • May 13, 2026

The Lesson

When BERT introduced the Masked Language Model (MLM) task, it presented a clever twist on traditional language modeling. Instead of predicting the next token from context (like GPT), MLM asks the model to fill in blanks — a "cloze test" on steroids. Given I [MASK] you because you are [MASK], the model predicts love and wonderful. This bidirectional approach lets the model use both the preceding and following context, which is why BERT excels at understanding tasks.

But there's a fundamental problem with naive MLM: the training distribution doesn't match inference. During pre-training, the model sees [MASK] tokens everywhere. During fine-tuning and inference, those tokens disappear entirely. The model never learns to handle a sentence without artificial masks. This distribution mismatch hurts downstream performance — a phenomenon known as pre-training/fine-tuning mismatch.

The BERT authors solved this with the 80/10/10 masking strategy. When MLM selects 15% of tokens to mask, it doesn't replace all of them with [MASK]. Instead, it applies a three-way split:

  • 80% of the time — Replace the token with [MASK]. This is the standard MLM signal: the model learns to predict the original token from its context.
  • 10% of the time — Replace the token with a random token from the vocabulary. This forces the model to pay attention to context rather than just learning "the token after [MASK] is always X." If every masked position were literally [MASK], the model could exploit that positional shortcut. Random tokens prevent this cheat.
  • 10% of the time — Leave the token unchanged. This is the most subtle part. By sometimes keeping the original token, the model occasionally sees training examples that look exactly like inference-time inputs (no masks at all). This bridges the pre-training/fine-tuning gap.

The net effect is elegant: the model learns to predict tokens when they're masked (80%), to verify tokens when they might be wrong (10%), and to process tokens normally when nothing is masked (10%). This three-pronged approach makes MLM robust enough that the resulting embeddings work well for virtually any downstream task.

Later improvements like RoBERTa went further by using dynamic masking instead of static masking. In BERT's original implementation, the mask positions were fixed during data preprocessing, meaning the same tokens were masked across all 40 epochs of training. RoBERTa moved masking to the training loop itself, so every epoch sees different mask positions. This makes the training data effectively infinite and is now the standard approach in all modern MLM implementations.

Concrete Example

The 80/10/10 Strategy in Code

Here's how to implement the masking strategy from scratch:

import torch
import torch.nn.functional as F
import random

def apply_mlm_masking(
    input_ids: torch.Tensor,
    tokenizer,
    mask_prob: float = 0.15
) -> tuple:
    """
    Apply BERT-style 80/10/10 MLM masking to tokenized input.

    Args:
        input_ids: Token IDs of shape (seq_len,)
        tokenizer: A tokenizer with a [MASK] and [PAD] token
        mask_prob: Fraction of tokens to select for masking

    Returns:
        masked_ids: Input with masking applied
        labels: -100 for non-masked positions, original token ID for masked
    """
    seq_len = input_ids.shape[0]
    vocab_size = tokenizer.vocab_size
    mask_token_id = tokenizer.mask_token_id
    pad_token_id = tokenizer.pad_token_id

    # Create a mask: randomly select ~15% of non-special tokens
    # Don't mask [PAD] or special tokens
    special_tokens = {tokenizer.cls_token_id, tokenizer.sep_token_id, pad_token_id}
    candidate_mask = torch.ones(seq_len, dtype=torch.bool)
    for i in range(seq_len):
        if input_ids[i].item() in special_tokens:
            candidate_mask[i] = False

    # Randomly select tokens to mask
    num_to_mask = max(1, int(mask_prob * candidate_mask.sum().item()))
    indices = torch.where(candidate_mask)[0]
    mask_indices = indices[torch.randperm(len(indices))[:num_to_mask]]

    masked_ids = input_ids.clone()
    labels = torch.full_like(input_ids, fill_value=-100)  # -100 = ignore in loss
    labels[mask_indices] = input_ids[mask_indices]  # save original tokens

    # Apply 80/10/10 strategy for each selected position
    for idx in mask_indices:
        r = random.random()
        if r < 0.8:
            # 80%: replace with [MASK]
            masked_ids[idx] = mask_token_id
        elif r < 0.9:
            # 10%: replace with random token (not the original or [MASK])
            candidates = list(range(vocab_size))
            candidates.remove(input_ids[idx].item())
            candidates.remove(mask_token_id)
            masked_ids[idx] = random.choice(candidates)
        # else 10%: leave unchanged (do nothing)

    return masked_ids, labels

How the Loss Works

The labels tensor uses -100 as a sentinel value. PyTorch's CrossEntropyLoss ignores positions with label -100, so the loss is only computed on the masked positions: 

# Model outputs logits of shape (seq_len, vocab_size)
logits = model(masked_ids)  # [8, 30522]

loss_fn = torch.nn.CrossEntropyLoss(ignore_index=-100)
loss = loss_fn(logits.view(-1, vocab_size), labels.view(-1))
# Only the masked positions contribute to the gradient

Key Takeaway: The 80/10/10 strategy is BERT's answer to the pre-training/fine-tuning mismatch problem. By sometimes masking, sometimes randomizing, and sometimes leaving tokens alone, the model learns to handle all three scenarios — making the transition from pre-training to fine-tuning seamless. Without the 10% "leave unchanged" rule, BERT's embeddings would degrade noticeably on downstream tasks.

Why It Matters

For practitioners building encoder models: If you're pre-training a BERT-like model on domain-specific data (medical texts, legal documents, code), using the naive "always replace with [MASK]" approach will give you measurably worse fine-tuning results. The 80/10/10 strategy is a free upgrade that costs nothing extra in compute.

For understanding modern LLMs: While decoder-only LLMs (GPT, LLaMA) don't use MLM, the masking concept lives on in techniques like span corruption (T5), denoising autoencoding (BART), and next-token prediction with context masking. The core insight — that controlled corruption of input data teaches robustness — applies across all pre-training paradigms.

For debugging model behavior: When a pre-trained encoder model underperforms on fine-tuning, one common culprit is a mismatch between pre-training and fine-tuning distributions. The 80/10/10 strategy was the first systematic solution to this class of problem, and it remains relevant whenever you're bridging unsupervised pre-training with supervised fine-tuning.
