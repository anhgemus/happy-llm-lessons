Lesson 05 Architecture

Building a Transformer from Scratch

Positional encoding, encoder-decoder layers, residual connections, and the complete forward pass.

Source: Happy LLM, Chapter 2 — Transformer Architecture · Published 2025-07-12

The Lesson

Lesson 02 covered the attention mechanism in isolation. This lesson shows how attention fits into the complete Transformer architecture — the actual model structure that every LLM is built on. The Transformer is not just attention; it's a carefully orchestrated pipeline of components, each solving a specific problem that attention alone cannot.

The core challenge: attention is permutation-invariant. If you shuffle the tokens in a sentence, attention computes the same scores. "I like you" and "you like I" produce identical attention patterns because attention only looks at vector similarity, not token order. The Transformer solves this with positional encoding — adding a sinusoidal signal to each token's embedding that encodes its position in the sequence. The formula uses sine and cosine at different frequencies so the model can learn both absolute positions and relative distances between tokens.

Once tokens are positionally encoded, they flow through the encoder-decoder pipeline. The encoder uses self-attention (where Q, K, V all come from the same input) to build a context-rich representation of the entire input sequence. The decoder uses two attention mechanisms: masked self-attention (each token can only attend to previous tokens — preventing the model from "cheating" by seeing future information during training) and cross-attention (the decoder queries the encoder's output to ground its predictions in the input). Each layer wraps its attention and feed-forward operations in residual connections (adding the input back to the output) and layer normalization (stabilizing the distribution of activations).

The residual connection pattern — x = x + SubLayer(LayerNorm(x)) — is critical. Without it, deep networks suffer from vanishing gradients: the signal from the loss function gets diluted as it propagates backward through dozens of layers. The residual connection provides a "highway" for gradients to flow directly from later layers to earlier ones. This is why Transformers with 20, 40, or even 100+ layers can be trained effectively. The "Pre-Norm" variant (layer norm before the sub-layer, not after) is the modern standard because it produces more stable training dynamics than the original "Post-Norm" design from the 2017 paper.

Positional Encoding: Why Sinusoidal?

The Transformer uses a fixed (non-learned) sinusoidal positional encoding:

PE(pos, 2i) = sin(pos / 100002i/dmodel)
PE(pos, 2i+1) = cos(pos / 100002i/dmodel)

Two key properties make this encoding superior to learned positional embeddings:

  • Extrapolation: If your training data has sentences up to 20 tokens, the formula can generate valid position encodings for a 21st token. Learned embeddings would have no representation for unseen positions.
  • Relative position awareness: Because sin(A+B) = sin(A)cos(B) + cos(A)sin(B), the encoding at position (pos + k) can be computed as a linear transformation of the encoding at position pos. This means the model can learn to recognize relative distances — "the word 3 positions ago" — rather than just absolute positions.

🎵 Frequency Analogy

Think of each dimension of the positional encoding as a musical note at a different frequency. Low-frequency dimensions (large wavelengths) encode coarse position — "somewhere in the first half of the sentence." High-frequency dimensions (small wavelengths) encode fine-grained position — "the third word." Together, they form a unique position fingerprint, like a musical chord that identifies a specific moment in time.

Concrete Example

Here's a complete positional encoding implementation that generates the sinusoidal encoding matrix:

import torch
import math

class PositionalEncoding(torch.nn.Module):
    """Sinusoidal positional encoding — the original Transformer approach."""

    def __init__(self, max_seq_len: int, d_model: int, base: float = 10000.0):
        super().__init__()
        # Build the positional encoding matrix: (max_seq_len, d_model)
        pe = torch.zeros(max_seq_len, d_model)
        position = torch.arange(0, max_seq_len, dtype=torch.float).unsqueeze(1)

        # Compute theta values: 1 / base^(2i / d_model) for each dimension pair
        div_term = torch.exp(torch.arange(0, d_model, 2, dtype=torch.float)
                             * -(math.log(base) / d_model))

        # Apply sin to even indices, cos to odd indices
        pe[:, 0::2] = torch.sin(position * div_term)
        pe[:, 1::2] = torch.cos(position * div_term)

        # Register as buffer (not a parameter, but tracks with the module)
        self.register_buffer("pe", pe.unsqueeze(0))  # (1, max_seq_len, d_model)

    def forward(self, x: torch.Tensor) -> torch.Tensor:
        """Add positional encoding to token embeddings.

        Args:
            x: Token embeddings of shape (batch, seq_len, d_model)
        Returns:
            Embeddings + positional encoding, same shape
        """
        return x + self.pe[:, :x.size(1)]


# --- Demo ---
pe = PositionalEncoding(max_seq_len=10, d_model=8)

# Simulate token embeddings for a 4-token sentence
embeddings = torch.randn(1, 4, 8)  # (batch=1, seq_len=4, d_model=8)
encoded = pe(embeddings)

print("Positional encoding for first 4 positions (d_model=8):")
print(pe.pe[0, :4].round(4))
print(f"\nOriginal shape: {embeddings.shape}")
print(f"Encoded shape:  {encoded.shape}")

Now, here's how a complete Transformer encoder layer assembles its components — attention, feed-forward, residual connections, and layer normalization:

import torch.nn as nn
import torch.nn.functional as F

class TransformerEncoderLayer(nn.Module):
    """One layer of the Transformer encoder.

    Architecture:
        input -> LayerNorm -> MultiHeadSelfAttention -> residual add ->
               -> LayerNorm -> FeedForward -> residual add -> output
    """

    def __init__(self, d_model: int, n_heads: int, dropout: float = 0.1):
        super().__init__()
        self.attention = nn.MultiheadAttention(d_model, n_heads, dropout=dropout, batch_first=True)
        self.feed_forward = nn.Sequential(
            nn.Linear(d_model, d_model * 4),  # expand to 4x
            nn.GELU(),                          # non-linearity
            nn.Dropout(dropout),
            nn.Linear(d_model * 4, d_model),   # project back
            nn.Dropout(dropout),
        )
        self.norm1 = nn.LayerNorm(d_model)
        self.norm2 = nn.LayerNorm(d_model)

    def forward(self, x: torch.Tensor) -> torch.Tensor:
        # Sub-layer 1: Self-attention with residual connection
        attn_out, _ = self.attention(x, x, x)  # Q=K=V=x for self-attention
        x = x + attn_out                       # residual: input + attention output

        # Sub-layer 2: Feed-forward with residual connection
        ff_out = self.feed_forward(self.norm2(x))
        x = x + ff_out                         # residual: input + FFN output

        return x


# --- Demo: a 3-layer encoder ---
d_model = 64
n_layers = 3
encoder_layers = nn.Sequential(*[TransformerEncoderLayer(d_model, 4) for _ in range(n_layers)])

# Simulate positionally encoded input: batch=2, seq_len=10, d_model=64
input_seq = torch.randn(2, 10, d_model)
output = encoder_layers(input_seq)

print(f"Input shape:  {input_seq.shape}")   # torch.Size([2, 10, 64])
print(f"Output shape: {output.shape}")       # torch.Size([2, 10, 64])

The decoder layer adds a second attention mechanism — cross-attention — that lets the decoder query the encoder's output:

class TransformerDecoderLayer(nn.Module):
    """One layer of the Transformer decoder.

    Architecture:
        1. Masked self-attention (decoder attends to itself, future masked)
        2. Cross-attention (decoder queries encoder output)
        3. Feed-forward network
    """

    def __init__(self, d_model: int, n_heads: int, dropout: float = 0.1):
        super().__init__()
        self.masked_attn = nn.MultiheadAttention(d_model, n_heads, dropout=dropout, batch_first=True)
        self.cross_attn = nn.MultiheadAttention(d_model, n_heads, dropout=dropout, batch_first=True)
        self.feed_forward = nn.Sequential(
            nn.Linear(d_model, d_model * 4), nn.GELU(), nn.Dropout(dropout),
            nn.Linear(d_model * 4, d_model), nn.Dropout(dropout),
        )
        self.norm1 = nn.LayerNorm(d_model)
        self.norm2 = nn.LayerNorm(d_model)
        self.norm3 = nn.LayerNorm(d_model)

    def forward(self, x: torch.Tensor, encoder_out: torch.Tensor,
                mask: torch.Tensor = None) -> torch.Tensor:
        # 1. Masked self-attention: decoder only sees past tokens
        attn1, _ = self.masked_attn(x, x, x, attn_mask=mask)
        x = x + attn1
        x = self.norm1(x)

        # 2. Cross-attention: decoder queries encoder output
        attn2, _ = self.cross_attn(x, encoder_out, encoder_out)
        x = x + attn2
        x = self.norm2(x)

        # 3. Feed-forward
        ff = self.feed_forward(x)
        x = x + ff
        x = self.norm3(x)

        return x
Key Takeaway: The Transformer is not just attention — it's a pipeline. Positional encoding gives the model a sense of order. Self-attention builds context-aware representations. Residual connections prevent gradient vanishing in deep stacks. Layer normalization stabilizes training. Masked attention enforces causal prediction. Each component solves a specific problem, and the architecture is the careful arrangement of these pieces into a trainable system. When you read "GPT-4 has 128 attention heads across 80 layers," you're reading a specification of how many of these building blocks are stacked together.

Why It Matters

For model debugging: When a model hallucinates or loses context in long sequences, the problem is often traceable to a specific component. If the model can't distinguish word order, positional encoding is the suspect. If the model forgets early context, attention depth or residual connections may be the bottleneck. Understanding the architecture lets you diagnose, not just guess.

For architecture choices: Modern LLMs (GPT, LLaMA, Mistral) use decoder-only architectures — they dropped the encoder entirely. But the encoder-decoder pattern lives on in translation models (NLLB), multimodal models (Flamingo, BLIP), and retrieval-augmented systems. Knowing the full architecture helps you choose the right variant for your task.

For training stability: The Pre-Norm vs Post-Norm debate is not academic. Pre-Norm (layer norm before the sub-layer) is now the universal standard because it prevents the gradient explosion that plagued early Transformer training runs. If you're building a custom model, this is one of the first decisions you make — and getting it wrong means your model won't train.

For efficiency: Every layer you add doubles the sequence of operations. A 32-layer model like LLaMA-3 processes each token through 32 attention heads × 32 layers = 1,024 attention computations per token. Understanding the layer structure helps you reason about inference speed, memory usage, and the tradeoffs between model depth and width.
