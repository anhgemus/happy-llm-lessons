BERT and the Masked Language Model

How masking random words taught models to understand context bidirectionally — the pre-training task that defined an era of NLP.

Chapter 3 Pre-training

The Lesson

Before BERT, language models were unidirectional — they read text left-to-right, like a person reading a sentence. The causal language model (CLM) predicts the next word given all previous words. This works great for text generation, but it has a blind spot: it can never see what comes next. If you're trying to understand the word "bank" in "I went to the river bank," a left-to-right model only sees "I went to the river" — which helps — but it misses downstream context entirely.

BERT's breakthrough was the Masked Language Model (MLM) pre-training task, which works like a cloze test (fill-in-the-blank). Instead of predicting the next word, BERT randomly masks 15% of tokens in a sentence and asks the model to predict them using both the words before and after the mask. For example:

Input:  "I [MASK] you because you are [MASK]"
Target: "I love you because you are wonderful"

To predict "love," the model sees both "I ___ you" and "because you are wonderful" — bidirectional context. This is why BERT dominated natural language understanding (NLU) tasks: classification, question answering, named entity recognition. It learned to represent words in the context of their full surroundings, not just what preceded them.

But there's a catch. During pre-training, the model sees [MASK] tokens. During fine-tuning and inference, there are no masks — the model receives complete text. This pre-training/fine-tuning mismatch could hurt downstream performance. The BERT authors solved it with an elegant trick: the 80/10/10 masking strategy.

When BERT selects 15% of tokens to mask, it doesn't always replace them with [MASK]. For each selected token:

  • 80% of the time: Replace with [MASK] — the standard cloze task.
  • 10% of the time: Replace with a random token — forces the model to rely on surrounding context rather than just learning "mask = predict the original word here."
  • 10% of the time: Leave the token unchanged — the model must still "predict" it, bridging the gap between pre-training (where masks exist) and fine-tuning (where they don't).

This means the model learns to be robust: it can't simply memorize that [MASK] always signals a prediction target. The random replacements force it to maintain rich contextual representations for every position, and the unchanged tokens ensure the distribution of inputs during pre-training overlaps with what it sees during fine-tuning.

Concrete Example

Here's how BERT's 80/10/10 masking strategy works in practice:

import random
import torch
from transformers import BertTokenizer, BertForMaskedLM

# Load pre-trained BERT tokenizer and model
tokenizer = BertTokenizer.from_pretrained("bert-base-uncased")
model = BertForMaskedLM.from_pretrained("bert-base-uncased")

# Example sentence
sentence = "The quick brown fox jumps over the lazy dog"
tokens = tokenizer.tokenize(sentence)
print(f"Tokens: {tokens}")
# ['the', 'quick', 'brown', 'fox', 'jumps', 'over', 'the', 'lazy', 'dog']

MASK_TOKEN = "[MASK]"
MASK_ID = tokenizer.mask_token_id
vocab_size = len(tokenizer)

def bert_masking(tokens, mask_ratio=0.15):
    """Apply BERT's 80/10/10 masking strategy."""
    masked_tokens = list(tokens)
    num_to_mask = max(1, int(len(tokens) * mask_ratio))
    mask_positions = random.sample(range(len(tokens)), num_to_mask)

    for pos in mask_positions:
        r = random.random()
        if r < 0.8:
            # 80%: replace with [MASK]
            masked_tokens[pos] = MASK_TOKEN
        elif r < 0.9:
            # 10%: replace with random token
            masked_tokens[pos] = tokenizer.decode(random.randint(100, vocab_size))
        else:
            # 10%: keep the original token (but still a prediction target)
            pass  # unchanged

    return masked_tokens, mask_positions

# Run masking
masked, positions = bert_masking(tokens)
print(f"Masked: {masked}")
print(f"Masked positions: {positions}")

# Encode and predict
inputs = tokenizer(" ".join(masked), return_tensors="pt")
model.eval()
with torch.no_grad():
    outputs = model(**inputs)
    logits = outputs.logits  # shape: (1, seq_len, vocab_size)

# Check predictions at masked positions
input_ids = inputs.input_ids[0]
for pos in positions:
    predicted_id = logits[0, pos].argmax().item()
    predicted_token = tokenizer.decode([predicted_id])
    original_token = tokens[pos]
    print(f"  Position {pos}: original='{original_token}', predicted='{predicted_token}'")

The output might look like:

  Position 2: original='brown', predicted='brown'    ✓
  Position 5: original='over',  predicted='over'     ✓
  Position 7: original='lazy',  predicted='sleepy'   (close!)

Notice that BERT doesn't always predict the exact original word — it predicts tokens that are contextually appropriate. "Sleepy" instead of "lazy" is a reasonable prediction given the context "the ___ dog." This is the power of bidirectional context: the model understands the meaning of the sentence, not just memorizing patterns.

🔑 Key Takeaway

BERT's MLM task with the 80/10/10 masking strategy is a masterclass in pre-training design. It gives models bidirectional context (unlike causal LM), while the randomized masking prevents the model from overfitting to the [MASK] token itself. The result: representations that transfer powerfully to downstream tasks with minimal fine-tuning.

Why It Matters

Even in the LLM era, MLM remains relevant. Modern models like RoBERTa (which removed NSP and used dynamic masking) and DeBERTa (which separated content and position embeddings) still build on BERT's MLM foundation. For tasks where you have labeled data and need maximum accuracy — sentiment analysis, named entity recognition, document classification — a fine-tuned BERT variant often outperforms prompting a large LLM, at a fraction of the inference cost.

Understanding MLM also helps you understand why Decoder-Only models (like GPT and LLaMA) took a different path. They chose causal LM for generation capability, accepting the trade-off of unidirectional context. The architecture choice — Encoder-Only with MLM vs. Decoder-Only with CLM — is still one of the most important decisions when building or selecting an LLM for a specific task.
