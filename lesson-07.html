Lesson 07 Chapter 4

Emergent Abilities — When Scale Changes Everything

Source: Happy-LLM Chapter 4 — Large Language Models • May 13, 2026

The Lesson

In physics, a phase transition is a dramatic shift in behavior caused by a gradual change in conditions. Water doesn't slowly become ice — at a critical temperature, it flips from liquid to solid. Emergent abilities in LLMs follow the same pattern: the same architecture and training objective, scaled up, suddenly exhibit capabilities that smaller versions of the same model lack entirely.

The term "emergent ability" refers to capabilities that are barely visible in small models but become pronounced once the model crosses a certain scale threshold. This is not a smooth, linear improvement — it's a qualitative leap. A 1B-parameter model might fail at basic arithmetic reasoning, while a 7B-parameter model of the same architecture can solve multi-step math problems. The architecture didn't change. The training task didn't change. Only the scale did.

Four emergent abilities define the LLM era:

  • In-context learning: The model can learn from examples provided in the prompt — no gradient updates required. Give it three translation examples, and it translates the fourth. This paradigm shift means most NLP tasks no longer require fine-tuning; they require prompt engineering.
  • Instruction following: After instruction-tuning on diverse commands, the model generalizes to instructions it has never seen. It doesn't need task-specific training data — it understands the concept of following instructions.
  • Chain-of-thought reasoning: When prompted to "think step by step," large models generate intermediate reasoning steps and arrive at correct answers for problems that stump smaller models. This ability may emerge from training on code, where step-by-step logic is inherent.
  • Multilingual transfer: Trained on multilingual corpora, LLMs develop cross-lingual abilities without explicit translation training. A model trained primarily on English data can still process Chinese, Arabic, or Swahili — with varying proficiency depending on corpus proportions.

The underlying mechanism is still debated, but the empirical evidence is overwhelming. The OpenAI scaling law C ≈ 6ND (where C is compute, N is parameters, D is tokens) predicts performance scaling, but it cannot predict the sharp discontinuities where new abilities appear. Emergence is the gap between what scaling laws predict and what we actually observe.

Concrete Example

1. Measuring Emergence with a Scaling Experiment

This example demonstrates how to evaluate a capability across model sizes to detect the emergence threshold. We use a simple arithmetic reasoning task and compare accuracy across different model scales. 

import torch
from transformers import AutoModelForCausalLM, AutoTokenizer

def evaluate_emergent_ability(model_name, task_prompt, correct_answer, temperature=0.0):
    """Evaluate a single model on a reasoning task."""
    tokenizer = AutoTokenizer.from_pretrained(model_name, trust_remote_code=True)
    model = AutoModelForCausalLM.from_pretrained(
        model_name, torch_dtype=torch.float16, device_map="auto"
    )

    inputs = tokenizer(task_prompt, return_tensors="pt").to(model.device)
    outputs = model.generate(
        **inputs,
        max_new_tokens=100,
        temperature=temperature,
        do_sample=temperature > 0,
    )
    response = tokenizer.decode(outputs[0], skip_special_tokens=True)
    return correct_answer in response, response

# Define models of increasing scale (same family)
model_sizes = [
    ("Qwen2.5-0.5B", "Qwen/Qwen2.5-0.5B"),
    ("Qwen2.5-1.5B", "Qwen/Qwen2.5-1.5B"),
    ("Qwen2.5-7B",   "Qwen/Qwen2.5-7B"),
]

# A reasoning task that requires multi-step logic
reasoning_task = """
Question: If a train travels 60 km/h for 2 hours, then 80 km/h for 1.5 hours,
what is the total distance traveled?
Think step by step:"""
correct = "240"

print(f"{'Model':<20} {'Pass':>6} {'Response preview'}")
print("-" * 60)
for label, name in model_sizes:
    passed, resp = evaluate_emergent_ability(name, reasoning_task, correct)
    preview = resp.split("step by step:")[-1][:80].strip()
    print(f"{label:<20} {'✓' if passed else '✗':>6} {preview}")

What to look for: The 0.5B model may compute individual distances but fail to sum them. The 7B model typically handles this correctly. The gap between failure and success is the emergent ability.

2. In-Context Learning — Zero Fine-Tuning

In-context learning means the model adapts to a new task purely from examples in the prompt. No weights are updated. Here's how to construct few-shot prompts that exploit this ability: 

def build_few_shot_prompt(task: str, examples: list, query: str) -> str:
    """
    Build a few-shot prompt for in-context learning.

    Args:
        task: Natural language description of the task
        examples: List of (input, output) tuples
        query: The new input to process

    Returns:
        A formatted prompt ready for the LLM
    """
    prompt = f"Task: {task}\n\n"
    for i, (inp, out) in enumerate(examples, 1):
        prompt += f"Example {i}:\nInput: {inp}\nOutput: {out}\n\n"
    prompt += f"Now complete:\nInput: {query}\nOutput:"
    return prompt

# Example: sentiment classification via in-context learning
examples = [
    ("The movie was absolutely terrible", "negative"),
    ("I loved every minute of this film", "positive"),
    ("The food was okay, nothing special", "neutral"),
]

prompt = build_few_shot_prompt(
    "Classify the sentiment of the following review as positive, negative, or neutral.",
    examples,
    "The plot was confusing but the cinematography was stunning"
)

print(prompt)
# Output:
# Task: Classify the sentiment of the following review...
#
# Example 1:
# Input: The movie was absolutely terrible
# Output: negative
#
# Example 2:
# Input: I loved every minute of this film
# Output: positive
#
# Example 3:
# Input: The food was okay, nothing special
# Output: neutral
#
# Now complete:
# Input: The plot was confusing but the cinematography was stunning
# Output:

Key insight: With a sufficiently large model, 3-5 examples are often enough to match or exceed the performance of a fine-tuned BERT on the same task. This eliminates the need for task-specific training data, labeled datasets, and GPU fine-tuning infrastructure.

3. Chain-of-Thought Prompting

Chain-of-thought (CoT) reasoning exploits the emergent ability of large models to break complex problems into intermediate steps: 

def chain_of_thought_prompt(question: str, cot_example: str = None) -> str:
    """
    Build a chain-of-thought prompt that encourages step-by-step reasoning.

    The key is showing the model HOW to reason, not just WHAT the answer is.
    """
    if cot_example:
        return f"""Here is an example of step-by-step reasoning:

{cot_example}

Now solve this problem using the same approach:

Question: {question}
Let's think step by step:"""
    else:
        return f"Question: {question}\nLet's think step by step:"

# Zero-shot CoT (no example needed for large models)
prompt = chain_of_thought_prompt(
    "A farmer has 17 sheep. All but 9 run away. How many sheep does the farmer have left?"
)

# With a CoT example (few-shot CoT)
cot_example = """Question: Roger has 5 tennis balls. He buys 2 more cans of tennis balls.
Each can has 3 tennis balls. How many tennis balls does he have now?
Let's think step by step:
1. Roger starts with 5 tennis balls.
2. Each can has 3 tennis balls, and he buys 2 cans: 2 × 3 = 6 balls.
3. Total: 5 + 6 = 11 tennis balls.
Answer: 11"""

prompt_with_example = chain_of_thought_prompt(
    "A store sells apples for $2 each and oranges for $3 each. "
    "If you buy 4 apples and 2 oranges, how much do you spend?",
    cot_example
)

Why this works: The "think step by step" prompt triggers the model's internal reasoning pathways. Research suggests this ability emerges from training on code and mathematical text, where step-by-step logic is the norm. Small models lack the capacity to maintain the intermediate state needed for multi-step reasoning.

Key Takeaway: Emergent abilities are not features you design — they are features you discover. The same Transformer architecture, trained with the same next-token-prediction objective, develops in-context learning, instruction following, and chain-of-thought reasoning only after crossing a scale threshold. This means the most powerful capabilities of LLMs are unintended consequences of scale, not engineered features.

Why It Matters

For practitioners: Emergent abilities mean you should always test with the largest model you can access before concluding a task is "impossible" for LLMs. A capability that fails on a 1B model may work perfectly on a 7B model with the same prompt.

For product builders: In-context learning has replaced fine-tuning for most applications. Instead of collecting labeled data and training a classifier, you write a few-shot prompt. This reduces development time from weeks to hours, but it also means your product's quality depends heavily on prompt design rather than model architecture.

For researchers: Emergence is still poorly understood theoretically. We can observe it, but we cannot reliably predict when it will occur. This creates both opportunity (new abilities waiting to be discovered at larger scales) and risk (unpredictable behavior at scale). The hallucination problem — models generating plausible but false information — is itself an emergent property that becomes more pronounced at larger scales.

For cost decisions: Understanding emergence helps you choose the right model size. If your task only needs text classification, a small model may suffice. If you need reasoning, instruction following, or few-shot adaptation, you likely need to cross the emergence threshold — typically 7B+ parameters.
