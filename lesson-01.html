The LLM Training Pipeline

Lesson #1 · May 9, 2026 · 5 min read

The Lesson

Training a production LLM isn't a single step — it's a pipeline with four distinct stages, each solving a different problem with a different data format and loss function.

1. Pre-training: Learning Language and Knowledge

Pre-training teaches the model basic language understanding and world knowledge. The model sees billions of tokens and learns to predict the next token in a sequence. The loss is computed on every token:

# Pre-training loss: predict next token for ALL positions import torch from transformers import AutoModelForCausalLM model = AutoModelForCausalLM.from_pretrained("meta-llama/Llama-2-7b-hf") text = "The capital of France is Paris. Paris is known for" inputs = tokenizer(text, return_tensors="pt") # Loss computed on ALL tokens outputs = model(**inputs, labels=inputs.input_ids) print(f"Pre-training loss: {outputs.loss.item():.4f}")

2. Supervised Fine-Tuning (SFT): Teaching Instruction Following

SFT transforms a language model into an assistant. The critical difference: you only compute loss on the response tokens, masking the instruction. This teaches the model to answer questions rather than just continue text.

# SFT: mask instruction tokens with -100 instruction = "What is 2+2?" response = "2+2 equals 4." # Tokenize instruction and response separately inst_ids = tokenizer(instruction, return_tensors="pt").input_ids resp_ids = tokenizer(response, return_tensors="pt").input_ids # Combine: [instruction tokens] + [response tokens] input_ids = torch.cat([inst_ids, resp_ids], dim=1) # Labels: -100 for instruction (ignored), actual IDs for response labels = torch.cat([ torch.full_like(inst_ids, -100), # Mask instruction resp_ids # Compute loss on response only ], dim=1) outputs = model(input_ids=input_ids, labels=labels) print(f"SFT loss: {outputs.loss.item():.4f}")
Key insight: The -100 label tells PyTorch's cross-entropy loss to ignore those positions. This is why SFT models learn to follow instructions instead of just continuing the prompt.

3. Parameter-Efficient Fine-Tuning (LoRA)

LoRA avoids updating all billions of parameters by injecting trainable low-rank matrices. For a weight matrix W of shape (d_model, d_ff), LoRA adds:

# LoRA: W' = W + B @ A # W is frozen, only A and B are trained import torch.nn as nn class LoRALayer(nn.Module): def __init__(self, d_model, d_ff, rank=8, alpha=16): super().__init__() self.rank = rank self.alpha = alpha # Low-rank decomposition self.A = nn.Linear(d_model, rank, bias=False) # (d_model, rank) self.B = nn.Linear(rank, d_ff, bias=False) # (rank, d_ff) # Scaling factor self.scale = alpha / rank def forward(self, x): # Original frozen weight original = self.frozen_weight(x) # LoRA update: B(A(x)) * scale lora_update = self.B(self.A(x)) * self.scale return original + lora_update

With rank=8, you're training 8 × d_model + 8 × d_ff parameters instead of d_model × d_ff. For a 7B model, this reduces trainable parameters from 7 billion to ~0.01%.

4. Preference Alignment (DPO)

Direct Preference Optimization (DPO) aligns model outputs with human preferences without training a separate reward model. Given a chosen response y_w and a rejected response y_l:

# DPO loss: optimize preference directly def dpo_loss(policy_logits_chosen, policy_logits_rejected, beta=0.1): """ DPO loss function beta: controls how strongly we enforce preferences """ # Log probability of chosen vs rejected log_policy_chosen = torch.log_softmax(policy_logits_chosen, dim=-1) log_policy_rejected = torch.log_softmax(policy_logits_rejected, dim=-1) # Preference margin log_ratio = log_policy_chosen - log_policy_rejected # DPO loss: minimize -log(σ(β * log_ratio)) loss = -torch.log(torch.sigmoid(beta * log_ratio)) return loss.mean()
Key Takeaway
The LLM training pipeline is a funnel: pre-training gives breadth (knowledge), SFT gives instruction-following, LoRA makes it affordable, and alignment makes it safe and helpful. Each stage uses a different loss function and data format.

Why It Matters

Understanding this pipeline helps you make architectural decisions:

  • Prompt vs Fine-tune: Prompting can only reach what pre-training encoded. Fine-tuning injects new behavior patterns.
  • LoRA vs Full FT: LoRA is sufficient for most domain adaptation. Full fine-tuning is only needed for fundamental capability changes.
  • Alignment needs: Most applications only need SFT. Alignment (RLHF/DPO) is only necessary when you need specific behavioral constraints.

As an AI leader, this knowledge helps you estimate costs, choose the right training approach, and debug when models don't behave as expected.
