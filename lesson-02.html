The Attention Mechanism — Core of Every LLM

Lesson #2 · May 10, 2026 · 6 min read

The Lesson

Every LLM — from GPT-4 to Llama 3 — runs on one fundamental operation: attention. Before Transformers, NLP relied on RNNs and LSTMs, which processed sequences one token at a time. This made them slow to train (no parallelism) and bad at capturing long-range dependencies (information fades as sequences get longer).

Attention solves both problems. The core idea is simple: instead of processing tokens sequentially, let every token look at every other token simultaneously and decide how much to "pay attention" to each one. This is fully parallelizable and captures relationships across arbitrary distances.

Query, Key, Value — The Attention Triad

Think of attention like searching a dictionary. You have a Query (what you're looking for), Keys (the dictionary entries), and Values (the definitions). Attention computes how similar your query is to each key, then uses those similarities as weights to combine the values.

For example, if your query is "fruit" and your keys are ["apple", "banana", "chair"], you'd want high weights for apple and banana, and near-zero for chair. The weighted combination of values gives you a representation of "fruit" distilled from the context.

The Scaled Dot-Product Formula

The mathematical formulation is elegant. Given matrices Q, K, V where each row is a token embedding:

Attention(Q, K, V) = softmax(QKT / √dk) V

Breaking it down step by step:

  1. QKT — Compute similarity between every query and every key using dot products. Higher dot product = more similar.
  2. / √dk — Scale by the square root of the key dimension. Without this, large dot products push softmax into regions with near-zero gradients, making training unstable.
  3. softmax — Convert similarities into a probability distribution (weights that sum to 1).
  4. × V — Weighted sum of values. Tokens your query cares about contribute more.

Self-Attention and Masked Attention

In self-attention, Q, K, and V all come from the same input — each token attends to every other token in the sequence. This lets the model learn relationships like pronoun resolution ("the bank by the river" — which meaning of "bank"?).

In masked attention, we add a causal mask that prevents each token from attending to future tokens. This is critical for language generation — when predicting the next word, the model should only use words it has already "seen." The mask is implemented by adding negative infinity to future positions before softmax, which makes their weights zero.

Multi-Head Attention

Single attention computes one type of relationship at a time. Multi-head attention runs multiple attention computations in parallel with different learned projections, allowing the model to capture different kinds of relationships simultaneously — syntactic structure in one head, semantic similarity in another, entity coreference in a third.

MultiHead(Q,K,V) = Concat(head1, ..., headh) WO

where each headi = Attention(QWiQ, KWiK, VWiV)

Concrete Examples

1. Attention from Scratch

import torch import torch.nn as nn import torch.nn.functional as F import math def attention(query, key, value, dropout=None): """ Scaled dot-product attention. Args: query: (batch, seq_len, d_k) - what we're looking for key: (batch, seq_len, d_k) - what we're searching through value: (batch, seq_len, d_v) - what we retrieve Returns: output: (batch, seq_len, d_v) - weighted combination of values attn_weights: (batch, seq_len, seq_len) - attention distribution """ d_k = query.size(-1) # Step 1: Compute similarity scores (Q @ K^T) / sqrt(d_k) scores = torch.matmul(query, key.transpose(-2, -1)) / math.sqrt(d_k) # Step 2: Softmax to get attention weights attn_weights = F.softmax(scores, dim=-1) # Step 3: Optional dropout if dropout is not None: attn_weights = dropout(attn_weights) # Step 4: Weighted sum of values output = torch.matmul(attn_weights, value) return output, attn_weights # Example usage batch_size, seq_len, d_model = 1, 4, 8 Q = torch.randn(batch_size, seq_len, d_model) K = torch.randn(batch_size, seq_len, d_model) V = torch.randn(batch_size, seq_len, d_model) output, weights = attention(Q, K, V) print(f"Output shape: {output.shape}") # (1, 4, 8) print(f"Attention weights:\n{weights}") # (1, 4, 4) - each row sums to 1

2. Causal Mask for Language Generation

# Create a causal mask: upper triangle = -inf (blocked) seq_len = 5 mask = torch.full((1, 1, seq_len, seq_len), float("-inf")) mask = torch.triu(mask, diagonal=1) print("Causal mask (before softmax):") print(mask[0, 0]) # Output: # [[ 0. -inf -inf -inf -inf] # [ 0. 0. -inf -inf -inf] # [ 0. 0. 0. -inf -inf] # [ 0. 0. 0. 0. -inf] # [ 0. 0. 0. 0. 0. ]] # After adding to scores and applying softmax, -inf becomes 0 scores = torch.randn(1, 1, seq_len, seq_len) masked_scores = scores + mask attn = F.softmax(masked_scores, dim=-1) print(f"\nEach row sums to 1: {attn.sum(dim=-1)}") print(f"Future positions are 0: {attn[0, 0, 0, 1:]}") # All zeros

3. Multi-Head Attention (Full Implementation)

class MultiHeadAttention(nn.Module): """ Multi-head self-attention with optional causal masking. The key insight: instead of n separate attention heads with n sets of weight matrices, we use 3 combined linear layers and reshape. This is mathematically equivalent but much faster. """ def __init__(self, dim, n_heads, max_seq_len=2048, dropout=0.0, causal=False): super().__init__() assert dim % n_heads == 0, "dim must be divisible by n_heads" self.head_dim = dim // n_heads self.n_heads = n_heads # Combined projection matrices: (dim) -> (n_heads * head_dim) self.wq = nn.Linear(dim, n_heads * self.head_dim, bias=False) self.wk = nn.Linear(dim, n_heads * self.head_dim, bias=False) self.wv = nn.Linear(dim, n_heads * self.head_dim, bias=False) self.wo = nn.Linear(n_heads * self.head_dim, dim, bias=False) # Output projection self.attn_dropout = nn.Dropout(dropout) self.resid_dropout = nn.Dropout(dropout) # Pre-compute causal mask if needed if causal: mask = torch.full((1, 1, max_seq_len, max_seq_len), float("-inf")) mask = torch.triu(mask, diagonal=1) self.register_buffer("mask", mask) def forward(self, x): bsz, seqlen, _ = x.shape # Project to Q, K, V: (B, T, dim) -> (B, T, n_heads * head_dim) xq, xk, xv = self.wq(x), self.wk(x), self.wv(x) # Reshape and transpose: (B, T, n_heads, head_dim) -> (B, n_heads, T, head_dim) xq = xq.view(bsz, seqlen, self.n_heads, self.head_dim).transpose(1, 2) xk = xk.view(bsz, seqlen, self.n_heads, self.head_dim).transpose(1, 2) xv = xv.view(bsz, seqlen, self.n_heads, self.head_dim).transpose(1, 2) # Attention: (B, nh, T, head_dim) @ (B, nh, head_dim, T) -> (B, nh, T, T) scores = torch.matmul(xq, xk.transpose(2, 3)) / math.sqrt(self.head_dim) # Apply causal mask if hasattr(self, 'mask'): scores = scores + self.mask[:, :, :seqlen, :seqlen] # Softmax + dropout attn = F.softmax(scores.float(), dim=-1).type_as(xq) attn = self.attn_dropout(attn) # Weighted sum: (B, nh, T, T) @ (B, nh, T, head_dim) -> (B, nh, T, head_dim) output = torch.matmul(attn, xv) # Merge heads: (B, nh, T, head_dim) -> (B, T, dim) output = output.transpose(1, 2).contiguous().view(bsz, seqlen, -1) # Output projection output = self.resid_dropout(self.wo(output)) return output # Example: 8-head attention on a short sequence mha = MultiHeadAttention(dim=256, n_heads=8, causal=True) x = torch.randn(2, 16, 256) # batch=2, seq=16, dim=256 out = mha(x) print(f"Input: {x.shape} -> Output: {out.shape}") # Input: torch.Size([2, 16, 256]) -> Output: torch.Size([2, 16, 256])
Why reshape instead of looping? Matrix multiplication is distributive over concatenation. Computing QW1, QW2, ..., QWn separately and concatenating is identical to computing Q × [W1; W2; ...; Wn] in one shot. This is why multi-head attention doesn't add computational overhead compared to single-head.
Key Takeaway
Attention is a differentiable lookup mechanism: it computes how similar each token is to every other token (via dot products), normalizes those similarities into weights (softmax), and uses those weights to blend information (weighted sum of values). The scaling factor √dk prevents gradient explosion. Multi-head attention lets the model learn multiple types of relationships in parallel.

Why It Matters

Understanding attention isn't just academic — it directly informs how you work with LLMs in practice:

  • Context window limits: Self-attention is O(n²) in sequence length. A 128K context window means ~16 billion attention computations per layer. This is why long-context models need optimized attention (flash attention, ring attention) and more VRAM.
  • Prompt engineering: When you put information early vs. late in a prompt, you're exploiting how attention distributes weights. Recency bias in LLMs is a direct consequence of attention patterns.
  • Model debugging: When a model fails to follow instructions, it's often an attention problem — the model's attention heads aren't properly focusing on the relevant parts of the prompt. Tools like TransformerLens let you visualize attention patterns to diagnose these failures.
  • Architecture choices: Knowing that causal masking prevents future token leakage explains why decoder-only models (GPT) are for generation and encoder-only models (BERT) are for understanding. The masking decision shapes the entire model's capabilities.

As someone building or deploying LLM applications, this knowledge helps you understand model limitations, estimate compute costs, and make informed decisions about architecture trade-offs.
